# XHeadphones - Прошивка и лаунчер

> Версия: 1.1
> Обновлено: 2026-09-29
> Связанные документы: [SOFTWARE.md](SOFTWARE.md),
> [PRODUCTION.md](PRODUCTION.md), [SPECIFICATIONS.md](SPECIFICATIONS.md)

Документ описывает состав прошивки и инструменты обновления. Структура кода,
задачи и очереди вынесены в [SOFTWARE.md](SOFTWARE.md), разделы 2-4.

## 1. Язык и инструменты

| Часть | Язык | Инструменты |
| --- | --- | --- |
| Прошивка `ESP32` | `C` | `ESP-IDF`, `FreeRTOS`, `CMake` |
| Загрузка образа | `Python` | `esptool` |
| Лаунчер | `Rust` | `Tauri` или `egui` |
| Документация | Markdown | `markdownlint` |

`Rust` рассматривался как альтернатива для прошивки, но для `ESP32` связка
`C` и `ESP-IDF` даёт готовый `BT`-стек `A2DP`, поэтому выбор сделан в пользу
`C`. `Rust` используется *только* в лаунчере на стороне ПК.

> **Оговорка.** Выбор `Tauri` или `egui` не зафиксирован: у них разные
> требования к системе и разный размер зависимостей. Решение принимается при
> старте лаунчера.

## 2. Модули прошивки

| Модуль | Назначение | Входит в образ |
| --- | --- | --- |
| `MCU Core` | Питание, кнопки, индикация, приоритет | Да |
| `Audio DSP` | Микширование, `EQ`, эффекты `12D` | Да |
| `Bluetooth Stack` | Сопряжение, аудио, управление | Да |
| `USB Stack` | Зарядка, данные, обновление | Да |
| `SD Card Controller` | Чтение файлов с `microSD` | Да |
| `Power Management` | Батарея, балансировка, приоритеты | Да |
| Модули ушек | Прошивка индикации ушек комплекта 1 | Отдельно |

Все модули основного образа обновляются **одним файлом**. Прошивка модулей
ушек заливается отдельно через `Pogo-Pin`, чтобы не трогать основной образ.

> **Оговорка.** Разделение на модули пока *логическое*: в коде это один
> статический образ. Понятие multi-patch и отдельная прошивка каждого модуля
> появляются только вместе с лаунчером.

## 3. Режимы работы

Режимы и их приоритет описаны в [ARCHITECTURE.md](ARCHITECTURE.md), раздел 3,
и в [CONCEPT.md](CONCEPT.md), раздел 1. Здесь только состав переключателя на
левой чаше.

| Кнопка | Значения | По умолчанию |
| --- | --- | --- |
| Режим | Шумоподавление, прозрачность | Шумоподавление |
| Источник | `Bluetooth`, `SD`-карта | `Bluetooth` |
| Питание | Включено, выключено | Выключено |

## 4. Индикация

Цвета и уровни заряда описаны в [SPECIFICATIONS.md](SPECIFICATIONS.md),
раздел 5.2. Прошивка ушек получает уровень заряда по `Pogo-Pin` и управляет
светодиодом локально, поэтому разряд батареи ушка не требует связи с `ESP32`.

> **Оговорка.** Ушки комплекта 1 питают только индикацию, а получение уровня
> заряда по `Pogo-Pin` требует пятой и шестой линии, назначение которых в
> [SPECIFICATIONS.md](SPECIFICATIONS.md), раздел 4.4 пока не определено.

## 5. Обновление модулей

Все обновления идут через порт `USB Type-C` кастомным лаунчером `XHeadphones`,
который поставляется с проектом.

| Вариант | Когда применяется |
| --- | --- |
| Проводная прошивка по `USB` | Первичная заливка, восстановление |
| `OTA` по `Wi-Fi` | Рабочее обновление без разборки |
| Через лаунчер | Набор модулей, настройка, диагностика |

Процедуры первичной заливки и `OTA`: [PRODUCTION.md](PRODUCTION.md), раздел 6.

> **Оговорка.** Кастомный лаунчер в проекте пока не написан: описан только его
> состав функций и структура каталогов. До его готовности обновление
> выполняется через `esptool`.

## 6. Лаунчер

### 6.1 Платформы

- **Windows**.
- **Linux**.

### 6.2 Функции

- **Прошивка наушников** целиком, multi-patch.
- **Прошивка отдельных модулей**: `MCU`, `Bluetooth`, `DSP`.
- **Настройка** эквалайзера и пространственных эффектов `12D`.
- **Мониторинг** состояния батареи.
- **Управление** режимами работы.
- **Управление файлами** на карте памяти.
- **Диагностика** модулей и чтение журнала.
- **Сброс настроек** к заводским.

### 6.3 Структура лаунчера

```text
launcher/
├── src/
│   ├── main.rs               # точка входа, окно приложения
│   ├── transport.rs          # USB и протокол обновления
│   ├── flashing.rs           # запись образа и контрольная сумма
│   ├── settings.rs           # настройки звука и режимов
│   ├── library.rs            # файлы на карте памяти
│   └── diagnostics.rs        # чтение журнала и состояния модулей
└── Cargo.toml
```

> **Оговорка.** Каталог `launcher/` в репозитории отсутствует, структура выше -
> замысел. Управление файлами на карте требует, чтобы устройство монтировало
> её как накопитель, а этот режим в прошивке не описан.

## 7. Планы развития

- `OTA`-обновление через `Bluetooth`.
- Раздельные образы `DSP` и `Bluetooth` для уменьшения размера `OTA`.
- Сохранение пользовательских настроек эквалайзера в `NVS` и синхронизация их
  через лаунчер.
