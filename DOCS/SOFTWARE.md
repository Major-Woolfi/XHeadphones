# XHeadphones - Микро-ОС на FreeRTOS

> Версия: 1.1
> Обновлено: 2026-09-29
> Связанные документы: [ARCHITECTURE.md](ARCHITECTURE.md),
> [PINOUT.md](PINOUT.md), [FIRMWARE.md](FIRMWARE.md)

## 1. Философия

ОС с нуля не пишется. Ядро - `FreeRTOS` в составе `ESP-IDF`, поверх него
прикладной слой из задач, очередей и драйверов. Этот прикладной слой и есть
*микро-ОС* в терминах проекта.

## 2. Структура проекта

Проект собирается как классический компонент `ESP-IDF`. Корневой каталог
сборки - `FIRMWARE/`, оттуда же запускаются скрипты `BUILD.sh` и `BUILD.bat`.

```text
XHeadphones/
└── FIRMWARE/
    ├── main/
    │   ├── main.c                 # точка входа, инициализация
    │   ├── config.h               # пины, тайминги, константы
    │   └── CMakeLists.txt
    ├── components/
    │   ├── audio/
    │   │   ├── i2s_dac.c          # драйвер PCM5102A
    │   │   ├── i2s_adc.c          # драйвер PCM1808
    │   │   ├── mixer.c            # микширование потоков
    │   │   └── dsp.c              # EQ, gain, эффекты 12D
    │   ├── bluetooth/
    │   │   ├── a2dp_sink.c        # приём с телефона
    │   │   ├── a2dp_source.c      # передача наружу
    │   │   └── avrcp.c            # управление с телефона
    │   ├── storage/
    │   │   ├── sd_card.c          # монтирование FAT32
    │   │   └── playlist.c         # плейлисты и навигация
    │   ├── codec/
    │   │   ├── mp3_dec.c          # libmad или helix
    │   │   ├── flac_dec.c         # dr_flac
    │   │   └── wav_dec.c          # встроенный декодер
    │   ├── ui/
    │   │   ├── buttons.c          # PCF8574, опрос с debounce
    │   │   ├── led.c              # SK6812 через RMT
    │   │   └── events.c           # очередь событий
    │   ├── power/
    │   │   ├── battery.c          # мониторинг ADC
    │   │   ├── power_path.c       # состояние USB и зарядки
    │   │   └── ota.c              # OTA-сервер
    │   └── system/
    │       ├── nvs.c              # настройки
    │       └── log.c              # логирование
    ├── CMakeLists.txt
    ├── BUILD.sh                   # сборка на Linux
    └── BUILD.bat                  # сборка на Windows
```

> **Оговорка.** Структура - *план*, а не факт: каталог `FIRMWARE/` содержит
> только скрипты сборки. Файлы компонентов, `CMakeLists.txt` и `config.h` ещё
> не созданы, поэтому `BUILD.sh` и `BUILD.bat` завершаются с ошибкой до
> появления `FIRMWARE/CMakeLists.txt`.

### 2.1 Ключевые макросы config.h

| Макрос | Значение | Раздел |
| --- | --- | --- |
| `CONFIG_AUDIO_SAMPLE_RATE` | 48000 Гц | [SPECIFICATIONS.md](SPECIFICATIONS.md) |
| `CONFIG_AUDIO_BITS` | 32 бит | [SPECIFICATIONS.md](SPECIFICATIONS.md) |
| `CONFIG_EXPANDER_ADDR` | `0x27`, адрес `PCF8574` | [PINOUT.md](PINOUT.md) |
| `CONFIG_BATT_DIVIDER` | 3.0, делитель 200 и 100 кОм | [POWER.md](POWER.md) |
| `CONFIG_BATT_LOW` | 6.0 В, порог перехода в сон | [POWER.md](POWER.md) |

> **Оговорка.** `CONFIG_AUDIO_SAMPLE_RATE` и `CONFIG_AUDIO_BITS` описывают
> формат шины `I2S`, а не формат файлов на карте. Декодирование `MP3` и `FLAC`
> идёт в `16` бит 44.1 кГц с последующим ресемплированием, иначе связка
> `I2S` и `A2DP` рассинхронизируется.

## 3. Задачи FreeRTOS

| Задача | Приоритет | Стек | Период | Назначение |
| --- | --- | --- | --- | --- |
| `task_bt` | 5 | 8 КБ | Событийный | `BT`-стек, `A2DP` и `AVRCP` |
| `task_audio` | 4 | 6 КБ | 5 мс | `I2S` `TX` и `RX`, микширование, `DSP` |
| `task_decode` | 4 | 8 КБ | Событийный | Декодирование `MP3`, `FLAC`, `WAV` |
| `task_sd` | 3 | 4 КБ | Событийный | `microSD` I/O и `FAT32` |
| `task_input` | 2 | 2 КБ | 20 мс | Кнопки и светодиод |
| `task_power` | 2 | 3 КБ | 500 мс | Батарея, Power Path, `OTA` |

Аудиозадача работает по **жёсткому таймеру**, остальные реагируют на события,
чтобы не тратить процессорное время.

> **Оговорка.** Приоритет 5 у `task_bt` означает, что `BT`-стек вытесняет
> аудиозадачу. На практике приоритет `task_audio` поднимается до 6, а
> `task_bt` получает 5, иначе возможны заикания при активном соединении.

## 4. Очереди и синхронизация

```c
/* --- Очередь событий от кнопок --- */
QueueHandle_t event_queue;    /* 16 элементов по 4 байта */

/* --- Аудиобуфер между декодером и I2S --- */
RingBuffer_t *audio_ring;     /* 32 КБ в PSRAM */

/* --- Семафор готовности карты --- */
SemaphoreHandle_t sd_ready;

/* --- Мьютекс доступа к NVS --- */
SemaphoreHandle_t nvs_mutex;
```

Правило приоритетов: `task_audio` не блокируется ни на чём дольше 5 мс, данные
для неё всегда в кольцевом буфере, а повреждённый фрагмент заменяется тишиной
вместо остановки потока.

## 5. Режимы и переключение

```c
typedef enum {
    MODE_OFF,
    MODE_BT_SINK,      /* приём с телефона */
    MODE_BT_SOURCE,    /* передача наружу */
    MODE_PLAYER,       /* плеер с карты памяти */
    MODE_TRANSPARENT,  /* прозрачность */
    MODE_NOISE_CANCEL, /* шумоподавление */
    MODE_OTA,          /* обновление прошивки */
} device_mode_t;
```

Переключение обрабатывается в `task_input` по событию кнопки режима:

```c
if (mode_button_pressed()) {
    device_mode_t next = get_next_mode(current_mode);
    stop_mode(current_mode);
    start_mode(next);
    current_mode = next;
}
```

> **Оговорка.** Режимы `MODE_NOISE_CANCEL` и `MODE_TRANSPARENT` отличаются
> только набором микрофонов и фильтром. Акустической обратной связи нет,
> поэтому `MODE_NOISE_CANCEL` - это усиление и фильтрация, а не классический
> `ANC`.

## 6. Аудиопотоки

### 6.1 Sink

```text
BT A2DP -> декодирование SBC или AAC -> кольцевой буфер -> I2S -> PCM5102A
```

### 6.2 Плеер

```text
microSD -> декодирование MP3 или FLAC -> кольцевой буфер -> I2S -> PCM5102A
```

### 6.3 Прозрачность и шумоподавление

```text
капсульные микрофоны -> PCM1808 -> I2S RX -> gain и EQ -> I2S TX -> PCM5102A
```

> **Оговорка.** Буфер 32 КБ в `PSRAM` рассчитан на 10 мс стерео в 32 бит. Для
> устойчивого воспроизведения `FLAC` с карты нужен буфер от 64 КБ, иначе
> считывание и декодирование не успевают за `I2S`.

## 7. Контроль питания

```c
void task_power(void *pv) {
    while (1) {
        bool usb = gpio_get_level(USB_DET);
        bool charging = !gpio_get_level(CHRG_STAT);

        /* --- Чтение напряжения батареи, делитель 1:3 --- */
        int raw = adc1_get_raw(ADC1_CHANNEL_0);
        float v_batt = (raw / 4095.0f) * 3.3f * 3.0f;

        /* --- Защита от переразряда --- */
        if (v_batt < 6.0f) {
            enter_deep_sleep();
        }

        /* --- События в очередь ввода --- */
        push_event(usb ? EV_USB_PLUGGED : EV_IDLE);
        push_event(charging ? EV_CHARGING : EV_IDLE);

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

Управление Power Path аппаратное, поэтому в прошивке нет вывода управления
затвором `MOSFET`, распиновка: [PINOUT.md](PINOUT.md), раздел 7.

> **Оговорка.** `GPIO 36` используется как канал `ADC1`, но на этом же канале
> нет фильтрации делителя. Гистерезис порога 6.0 В отсутствует, поэтому
> устройство может просыпаться и засыпать на границе. Порог задаётся
> макросом `CONFIG_BATT_LOW` и фильтруется средним за 10 отсчётов.

## 8. OTA

```c
void task_ota_start(void) {
    /* --- Поднять точку доступа или подключиться к сети --- */
    wifi_init_softap("XHeadphones-OTA", "12345678");
    /* --- Запустить HTTP-сервер и обработчик /update --- */
    httpd_handle_t server = start_webserver();
    /* --- После успешной заливки подтвердить загрузку --- */
    esp_ota_mark_app_valid_cancel_rollback();
}
```

> **Оговорка.** Точка доступа поднимается с заводским паролем из кода, это
> открытая сеть для любого рядом. Перед передачей устройства пользователю пароль
> должен задаваться при первом включении или вводиться вручную.

Разбиение `Flash` и процедура загрузки описаны в
[PRODUCTION.md](PRODUCTION.md), раздел 6.

## 9. Сборка прошивки

Сборка выполняется скриптами из каталога `FIRMWARE/`:

```bash
cd FIRMWARE
./BUILD.sh
```

Скрипт ставит `ESP-IDF`, собирает проект и заливает образ по `USB` или через
`OTA`. Подробности: [FIRMWARE.md](FIRMWARE.md).
